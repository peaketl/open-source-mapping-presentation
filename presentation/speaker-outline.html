Advance to PostGIS Concepts

Technical Deep Dives
5 PostGIS Concepts
  • What PostGIS is: a PostgreSQL extension that adds geometry types and spatial functions
  • Geometry types — keep it brief:
    • POINT — single location (what we use)
    • LINESTRING — roads, pipelines
    • POLYGON — neighborhoods, parcels
  • SRID / Coordinate systems:
    • SRID = Spatial Reference ID — a numeric code that tells PostGIS which coordinate system your data is in
    • 4326 = WGS 84, the system GPS uses — latitude and longitude in decimal degrees; this is what your phone gives you and what we store
    • 3857 = Web Mercator — a flat/projected system used by web maps; Martin and MapLibre handle the conversion automatically
    • Note: coordinate systems are a deep topic on their own — geodesy, datums, projections. For today, the rule is simple: store in 4326, let the stack reproject for display.
  • Spatial index: GiST index on geom — required for tile performance; without it tiles get slow at scale
  • Key functions on the slide: ST_MakePoint, ST_SetSRID, ST_GeomFromEWKT, ST_Distance
    • Note: always pass (lon, lat) order — x before y, just like a graph

Advance to PostGIS Queries

6 Raw PostGIS Queries DEMO
  • Open queries.sql in one terminal and a psql $DATABASE_URL shell in another
  • Tell the audience to flip their handout over — the eight queries are printed on the back; they can follow along or run them later
  • Query 1 — sanity check: count(*) split by solved — confirms the loader ran; reminds the audience this is ordinary SQL
  • Query 2 — ST_AsText: show what the geom column actually contains in human-readable WKT (Well-Known Text); dispels the mystery of the binary column
  • Query 3 — ST_AsGeoJSON: one function turns a row into a GeoJSON geometry object — same format the browser consumes
  • Query 4 — ST_DWithin (radius search):
    • Cast geom to ::geography — PostGIS switches from degrees to meters automatically
    • 1,609 metres = 1 mile — no manual projection math required
    • This is the core spatial query behind any "find nearby" feature
  • Query 5 — KNN with <-> operator:
    • The <-> distance operator is index-accelerated — it uses the GiST index, fast even at scale
    • Pattern: ORDER BY geom::geography <-> point::geography LIMIT N
  • Query 6 — aggregate by decade: clearance-rate calculation; PostGIS integrates seamlessly with normal SQL GROUP BY — no special treatment needed
  • Query 7 — ST_Buffer + ST_Within: build a circle polygon, count points inside — foundation of zone-of-interest analysis; change the radius to taste
  • Query 8 — ST_Centroid / ST_Collect: geographic center of all cases — one line; paste the result into Google Maps to verify it lands in Colorado Springs

Advance to Martin Concepts

7 Martin Concepts
  • What Martin is: open-source Rust tile server — points at PostGIS, serves MVT tiles automatically
  • Vector tiles (MVT):
    • Binary and compressed — much smaller than GeoJSON over the wire
    • Tile URL scheme: /{z}/{x}/{y} — zoom, column, row
    • Browser renders with WebGL; styling is 100% client-side
    • Tiles are cacheable by a CDN — scales cheaply
  • Martin endpoints:
    • /crimes — TileJSON metadata
    • /crimes/{z}/{x}/{y} — actual tile
    • /catalog — all published sources
    • /health — health check
  • Config (martin.yaml): four lines — connection string + auto_publish → done; no table registration needed

Advance to MapLibre GL JS

8 MapLibre GL JS Concepts
  • History: fork of Mapbox GL JS after Mapbox went proprietary in 2020; backed by AWS, Microsoft, Meta
  • How it works:
    • WebGL rendering — GPU-accelerated, smooth at 60fps
    • Consumes vector tiles directly from Martin
    • Style spec is JSON — layers, colors, filters all defined in code
  • In our app (app.js):
    • Basemap from OpenFreeMap — dark style, no API key
    • Two circle layers: halo + dot, colored by solved boolean
    • Sidebar + stats populated from local crimes.json
    • Click popup shows title, victim, year, weapon, description
  • Vanilla JS — no build step, no framework

Advance to Stack Configuration

Code Walkthrough
9 Stack Configuration DEMO
  • Show start.sh — everything in one script:
    • Stop + remove old containers
    • Build fresh images (PostGIS, Martin, Nginx)
    • Start PostGIS, wait for it to be ready
    • Run load_data.py to seed data
    • Start Martin, then Nginx
  • Briefly show the three Containerfiles — each is 3—5 lines
  • Point: no Docker Compose, no Kubernetes — just Podman CLI; easy to understand and debug
  • Podman + systemd:
    • In dev, we start everything from the CLI — that's what start.sh does
    • In production, Podman integrates with systemd: podman generate systemd produces unit files that auto-start containers on boot — no orchestrator needed
    • We haven't needed Kubernetes — the workloads we run don't require that level of horizontal scaling, and avoiding it keeps operations simple
    • Podman is also daemonless and rootless by default — better security posture than Docker

Advance to Database Schema

11 Database Schema
  • Schema lives in containers/postgis/schema.sql — auto-run on container first start
  • Most columns are plain text/int — same as any app table
  • The magic column: geom GEOMETRY(Point, 4326) — this is what Martin reads
  • Three indexes:
    • GiST on geom — spatial lookup for tile generation
    • B-tree on year and season — for sidebar filter queries
  • If you forget the GiST index, tile generation does a full table scan — painfully obvious at scale

Advance to Data Loader

12 Data Loader — load_data.py DEMO
  • ~60 lines of Python — reads JSON, bulk inserts with execute_values
  • DATABASE_URL from environment — no hardcoded credentials
  • ST_SetSRID(ST_MakePoint(lon, lat), 4326) inline in the INSERT — geometry built on the fly
  • ON CONFLICT DO NOTHING — idempotent; safe to re-run after adding cases
  • Only dependency: psycopg2-binary
